## Env vars

| Name                                   | Values                                         |
| -------------------------------------- | ---------------------------------------------- |
| `EXPO_PUBLIC_API_MODE`                 | `mock` (default) or `supabase`                 |
| `EXPO_PUBLIC_SUPABASE_URL`             | `https://<project>.supabase.co`                |
| `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | the publishable key only, never the secret key |

`EXPO_PUBLIC_*` values are baked in at build time: change `.env`, then rebuild.

## Tests

```bash
npm run test:app          # from the repo root
# which runs: node --experimental-strip-types --test "lib/__tests__/*.test.ts"
```

Files in `lib/__tests__/`: `account`, `api`, `detail`, `dwell`, `feedLogic`, `fixtures`, `format`, `labels`, `pagerLogic`, `sourceKeys`, `sourcesInfo` and `types` (each `<name>.test.ts`, covering the matching `lib/` file or topic) plus `helpers.ts` (card, data card, fact and config builders). Together they cover labels (no card kind renders without the disclaimer), formatting, guards, the feed reducer and mock paging, the Supabase request shape and error handling, the sample fixtures, and a scan for secret keys in `app/`, `components/` and `lib/`. On Node 23.6+ the flag is optional. A "module type" warning per file is harmless.

## Paging, errors and page-hide tracking (review items 3, 4, 9, 11, 12)

- **`feedLogic.ts` – `loadFeedPages`, `decidePage`, `shouldLoadMore`, `needsRefill`.** Paging looks at the list the reader can *see* (hidden topics and sources removed, the same filter the feed screen uses). A page that adds nothing visible keeps fetching, at most `MAX_EMPTY_HOPS` (3) extra pages. The chain always stops when `next_cursor` is null or repeats (any cursor already requested), so it cannot loop; a chain that ends this way marks the feed done. A list that filtered down to nothing while the server has more refills itself (`needsRefill`); an error never refills (retry shows instead). `useFeed(api, query, account, filter)` wires this to React.
- **`errors.ts`.** `friendlyHttpError(status, rawMessage, code)` maps HTTP and PostgREST errors (`invalid_cursor`, `unknown_card`, `PGRST301`, 42501, 4xx/5xx) to short sentences; `userMessage(err, fallback)` shows only our own `ApiError` / `AccountError` text and hides anything else (parse failures, TypeErrors). The raw text stays on the error as `.detail` and is printed with `console.warn` only when `__DEV__` is true. A rejected cursor makes Retry restart the list.
- **`labels.ts` – `disclaimerPlacement(hasReactions)`.** Decides where the disclaimer goes (in the footer row, or under the reaction buttons). Exactly one slot is ever true, so every card renders the disclaimer once (`__tests__/disclaimer.test.ts`).
- **`account.ts` – `trackDwellOnExit` and `planRpc`.** The last dwell on `pagehide` is sent with `fetch` `keepalive: true` and the user's auth header (`sendBeacon` cannot set headers). It uses the stored token as it is (nothing can be awaited while the page closes), is skipped when signed out or expired, and never throws.
- New tests: `errors`, `feedPaging`, `disclaimer` (`lib/__tests__/`).

## Search and Following helpers

- `searchLogic.ts`: 300 ms debounce, 2-character minimum, query normalising, the search target and list key, recent searches (add, remove, parse), wording. Tests: `__tests__/searchLogic.test.ts`.
- `followingLogic.ts`: the three follow lists (topics, sources, tickers), parse / toggle / ticker check, which topics come from the account, the "Because you follow X" text with topic slugs turned into names. Tests: `__tests__/followingLogic.test.ts` (includes the mock search and following feed).
- `useFollows.ts`: the follow lists for the screens (account topics when signed in, device storage otherwise).
- `usePagedCards.ts`: pages any card list by key (search, topic, follows) with the feed's rules: a new key starts over, late answers are dropped, hidden topics and sources are skipped.

## Signed-out readers (`localPrefs.ts`, `localRank.ts`)

- `localPrefs.ts`: what a signed-out reader chose, on this device only (`element.local-prefs` plus the shared `element.follows`): like/dislike per card id (with topic and source, newest 200 kept), hidden topics, hidden sources, favorite (= followed) topics. `asUserPrefs` gives it the account's shape; `favoritesFirst` orders chips; `mergeIntoAccount` is the one-time, idempotent union merged into the account on sign-in (account wins conflicts; flag `element.local-migrated.<uid>`). Tests: `__tests__/localPrefs.test.ts`.
- `localRank.ts`: signed-out For you. `rankLocal` re-orders one page of the public Trending feed: recency + importance, +24 h favorite topic, +8 h per like in the topic and +4 h per like from the source (max 3 each), the same minus for dislikes, disliked cards and hidden topics/sources dropped, then a diversity pass (6 h per same-topic card among the last 3 picked). Tests: `__tests__/localRank.test.ts`.
- `accountContext.tsx` exposes `viewPrefs` (account prefs when signed in, device prefs when signed out) and `localPrefs`; `react`, `savePrefs`, `hideTopic`, `restoreTopics`, `hideSource`, `saveSources` write to the device when signed out and send nothing.
- `storage.ts`: `onStoreChange(fn)` fires on every `defaultStore()` write, so the context sees a follow saved on the Following screen at once. Off web the memory store is shared app-wide.
- `useFeed(api, query, account, filter, rankPage?)`: signed out, For you calls the same public `api.feed` as Trending and applies `rankPage` per page (earlier pages never move).
